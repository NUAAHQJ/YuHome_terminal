# YuHome DAYU 分层 NLU 训练报告

## 结论

最终选择 `rbt3_yuhome_hierarchical_v4_seed20260802`。模型基于开源中文预训练模型 `hfl/rbt3`，在 AutoDL NVIDIA GeForce RTX 4090 上使用 CUDA 训练；最佳检查点为第 7 轮，训练阶段耗时 41.68 秒。

旧版扁平分类器 `rbt3_yuhome_nlu_v2` 正式拒收并被本版替代。它虽然有约 85.33% test macro-F1，但 test unknown 误接收率约 29.17%，ASR 场景确认漏判率约 43.75%，不满足智能家居控制安全要求。

本版采用“硬安全规则 → 三分类路由头 → 十三分类意图头 → 槽位规则”的分层架构。最终规则与模型的完整管线在 100 条安全对抗样本上达到 100% 准确率，unknown 误接收、unknown 转控制、确认绕过、取消命令执行和正常控制误阻断均为 0。

严格验收门槛同时要求：test macro-F1 ≥ 84%、ASR macro-F1 ≥ 82%、边界准确率 100%、安全对抗准确率 ≥ 99%，并且五类安全错误为 0。FP32 和混合 INT8 通过离线验收；全量 INT8 虽因硬规则保持安全，但质量明显不足，拒绝部署，其二进制未下载到交付包。

安全结果依赖硬规则和模型组成的完整管线，不能理解为 ONNX 裸模型能够独立保证安全。安全集最终规则覆盖率为 95%，剩余样本由分层模型正确处理。

## ONNX 与量化

FP32 ONNX 与 PyTorch 在 386 条验证集上的路由头和意图头 argmax 一致率均为 100%，最大绝对 logit 差约 `8.6e-6`。

混合 INT8 仅动态量化 encoder 第 1、2 层，embedding 和第 0 层保持 FP32，体积从 151,668,932 字节降到 109,245,278 字节。它通过离线质量与安全门槛，可以进入 DAYU 真机验证，但在 ARM64 延迟、内存、算子兼容性完成前不能标记为正式部署。

## DAYU 运行时接入与改动边界

现有规则 NLU、实时状态读取、`skipPrompt`、传感器数据门控和开门/解锁安全逻辑均被保留。在其基础上新增独立 NLU 原生 session、与 Hugging Face 一致的 BERT tokenizer、异步 NAPI 加载/推理接口和 ArkTS 分层调度。

运行时默认先加载混合 INT8，失败时尝试 FP32；初始化或推理失败时继续使用原规则解析器。硬安全规则始终先于模型执行，模型输出还要经过确定性槽位提取和温度/百分比范围复核。执行层已接通窗帘百分比、空调温度与空调模式，并将 `ac_power_set` 显式映射为 `ac_set`。本轮没有修改任何联邦学习文件。

使用的头文件是 ONNX Runtime v1.17.1 官方 C API 头文件。`sherpa_onnx 1.13.3` 随包运行库的动态符号版本为 1.16.3，因此运行时显式请求 C API 16；当前使用的接口均属于该兼容范围。隔离影子工程和实际 DAYU 仓库均已完成 ArkTS、C++、链接、打包和签名全流程构建。
